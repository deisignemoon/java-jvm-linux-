## 设计模式

这些模式主要分为三大类，你可以把它们想象成代码世界的"工具箱"，每个工具都有它独特的用途。（GoF 共 23 种）

### 一、 创建型模式（5种）

**关注"怎样更好地创建对象"，将对象的创建和使用分离。**

#### 1. 单例模式（Singleton）

**定义**：确保一个类只有一个实例，并提供一个全局访问点。

**关键词**：`唯一实例`、`全局访问点`、`getInstance()`

**典型场景**：日志管理器、线程池、配置中心、Windows 任务管理器、Spring 默认单例 Bean

**生活化示例**：一个公司只有一位 CEO，全公司都通过统一的"秘书处"联系他。

**Java 示例**：

```java
public class Singleton {
    private static volatile Singleton instance;   // volatile 防止指令重排

    private Singleton() { }                       // 私有构造器,禁止外部 new

    public static Singleton getInstance() {       // 全局访问点
        if (instance == null) {                   // 第一次检查(无锁,提高性能)
            synchronized (Singleton.class) {
                if (instance == null) {           // 第二次检查(加锁后)
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}
```

#### 2. 工厂方法模式（Factory Method）

**定义**：定义一个用于创建对象的接口，但让子类决定实例化哪一个类。这使得类的实例化延迟到子类中进行。

**关键词**：`定义创建对象的接口`、`子类决定实例化哪个类`、`实例化延迟到子类`、`一个工厂造一种产品`

**典型场景**：JDBC DriverManager、日志框架 LoggerFactory、Calendar.getInstance()

**生活化示例**：手机代工厂——苹果工厂只产 iPhone，华为工厂只产 Mate，各造各的。

**Java 示例**：

```java
interface Product { void use(); }

class ProductA implements Product {
    public void use() { System.out.println("使用产品A"); }
}

interface Factory {                        // 创建对象的接口
    Product createProduct();
}
class FactoryA implements Factory {        // 子类决定实例化哪一个类
    public Product createProduct() { return new ProductA(); }
}

// 使用:Product p = new FactoryA().createProduct();
```

#### 3. 抽象工厂模式（Abstract Factory）

**定义**：提供一个接口，用于创建一系列相关或相互依赖的对象，而无需指定它们具体的类。

**关键词**：`创建一系列相关对象`、`产品族`、`无需指定具体的类`

**典型场景**：跨平台 UI 组件族（Windows/Mac 的按钮+文本框）、换肤系统、多数据库访问层

**生活化示例**：肯德基全家桶——一次下单同时得到同一品牌的汉堡、薯条、可乐（一族产品）。

**Java 示例**：

```java
interface Button { void click(); }
interface Text   { void show(); }

class MacButton implements Button {
    public void click() { System.out.println("Mac按钮"); }
}
class MacText implements Text {
    public void show() { System.out.println("Mac文本框"); }
}

interface UIFactory {                      // 一个工厂创建一"族"相关产品
    Button createButton();
    Text createText();
}
class MacFactory implements UIFactory {
    public Button createButton() { return new MacButton(); }
    public Text createText()     { return new MacText(); }
}
```

#### 4. 建造者模式（Builder）

**定义**：将一个复杂对象的构建与它的表示分离，使得同样的构建过程可以创建不同的表示。

**关键词**：`构建与表示分离`、`分步构建`、`同样的构建过程创建不同的表示`、`链式调用`

**典型场景**：StringBuilder、Lombok @Builder、MyBatis SqlSessionFactoryBuilder、OkHttp Request.Builder

**生活化示例**：快餐店点套餐——服务员按固定流程问"主食？饮料？小食？"，不同选择组合出不同套餐。

**Java 示例**：

```java
class Computer {
    private final String cpu;
    private final String memory;
    private final String disk;

    private Computer(Builder b) {          // 构建过程交给 Builder
        this.cpu = b.cpu;
        this.memory = b.memory;
        this.disk = b.disk;
    }

    static class Builder {
        private String cpu, memory, disk;
        public Builder cpu(String c)    { this.cpu = c;    return this; }  // 链式调用
        public Builder memory(String m) { this.memory = m; return this; }
        public Computer build()         { return new Computer(this); }   // 统一出厂
    }
}

// 使用:new Computer.Builder().cpu("i9").memory("32G").build();
```

#### 5. 原型模式（Prototype）

**定义**：用原型实例指定创建对象的种类，并通过复制这个原型来创建新的对象。

**关键词**：`复制/克隆`、`clone()`、`拷贝创建新对象`、`浅拷贝与深拷贝`

**典型场景**：Object.clone() 与 Cloneable 接口、Spring 的 prototype 作用域、游戏中批量克隆相同怪物

**生活化示例**：复印文件——以第一份为原型复印出多份副本，再各自修改使用。

**Java 示例**：

```java
class Sheep implements Cloneable {
    String name;
    Sheep(String name) { this.name = name; }

    @Override
    protected Object clone() throws CloneNotSupportedException {
        return super.clone();              // 通过复制原型来创建新对象
    }
}

// 使用:Sheep dolly = (Sheep) original.clone();
```

### 二、 结构型模式（7种）

**关注"怎样将类和对象组合成更大的结构"，以形成更强大的功能。**

#### 1. 适配器模式（Adapter）

**定义**：将一个类的接口转换成客户希望的另一个接口，使得原本因接口不兼容而无法一起工作的类可以协同工作。

**关键词**：`转换接口`、`接口不兼容`、`无法一起工作的类协同工作`、`包装已有类`

**典型场景**：InputStreamReader（字节流转字符流）、Spring MVC 的 HandlerAdapter、旧系统接口兼容

**生活化示例**：出国旅行带的电源转换头——国标插头经它一转就能插进欧标插座。

**Java 示例**：

```java
interface Target { void request(); }       // 目标接口(客户期望的)

class Adaptee {                            // 被适配者(已有的、不兼容的)
    void specificRequest() { System.out.println("旧接口功能"); }
}

class Adapter implements Target {          // 适配器:实现目标接口 + 持有被适配者
    private Adaptee adaptee = new Adaptee();

    public void request() {
        adaptee.specificRequest();         // 做接口转换
    }
}
```

#### 2. 桥接模式（Bridge）

**定义**：将抽象部分与它的实现部分分离，使它们都可以独立地变化。

**关键词**：`抽象与实现分离`、`独立地变化`、`两个变化维度`、`避免类爆炸`

**典型场景**：JDBC（API 与各数据库驱动解耦）、消息类型 × 发送渠道、跨平台图形 API

**生活化示例**：遥控器（抽象）和电视机品牌（实现）分开生产——同一款遥控设计可配不同电视，双方各自升级互不影响。

**Java 示例**：

```java
interface Color {                          // 实现化角色(一个维度)
    String fill();
}
class Red implements Color {
    public String fill() { return "红色"; }
}

abstract class Shape {                     // 抽象化角色(另一个维度)
    protected Color color;                 // 桥:持有实现的引用
    Shape(Color color) { this.color = color; }
    abstract void draw();
}
class Circle extends Shape {
    Circle(Color color) { super(color); }
    void draw() { System.out.println(color.fill() + "的圆形"); }
}
```

#### 3. 组合模式（Composite）

**定义**：将对象组合成树形结构以表示"部分-整体"的层次结构，使得用户对单个对象和组合对象的使用具有一致性。

**关键词**：`树形结构`、`部分-整体`、`单个对象和组合对象一致性使用`

**典型场景**：文件目录树（文件+文件夹）、GUI 容器组件、公司组织架构

**生活化示例**：公司组织架构——员工和部门都能"统计人数"，老板的操作方式完全一致。

**Java 示例**：

```java
abstract class Component {                 // 叶子与容器的统一抽象
    abstract void display(int depth);
}

class Leaf extends Component {             // 叶子节点
    private final String name;
    Leaf(String name) { this.name = name; }
    void display(int depth) { System.out.println("-".repeat(depth) + name); }
}

class Composite extends Component {        // 容器节点:树形结构
    private final String name;
    private final List<Component> children = new ArrayList<>();
    Composite(String name) { this.name = name; }
    void add(Component c) { children.add(c); }
    void display(int depth) {
        System.out.println("+".repeat(depth) + name);
        for (Component c : children) c.display(depth + 2);   // 递归处理
    }
}
```

#### 4. 装饰器模式（Decorator）

**定义**：动态地给一个对象添加一些额外的职责。就增加功能来说，它比生成子类更为灵活。

**关键词**：`动态添加职责`、`比继承更灵活`、`不加子类增加功能`、`层层包装`

**典型场景**：Java IO 流（new BufferedInputStream(new FileInputStream(...))）、给接口动态加缓存/日志

**生活化示例**：点奶茶——基础奶茶上依次"加珍珠""加奶盖"，每加一层口味价格动态叠加，不必为每种组合单设品类。

**Java 示例**：

```java
interface Coffee { double cost(); }

class SimpleCoffee implements Coffee {     // 被装饰的基础对象
    public double cost() { return 10; }
}

abstract class Decorator implements Coffee {   // 装饰器本身也是 Coffee
    protected Coffee coffee;                   // 包装被装饰对象
    Decorator(Coffee coffee) { this.coffee = coffee; }
}

class Milk extends Decorator {
    Milk(Coffee coffee) { super(coffee); }
    public double cost() { return coffee.cost() + 2; }   // 动态叠加职责
}

// 使用:new Milk(new Milk(new SimpleCoffee())).cost();
```

#### 5. 外观模式（Facade）

**定义**：为子系统中的一组接口提供一个一致的界面，定义了一个高层接口，使得这一子系统更加容易使用。

**关键词**：`一组接口提供一个一致的界面`、`高层接口`、`子系统更容易使用`

**典型场景**：SLF4J 日志门面、一键开机、医院导诊台、Service 层封装多个 DAO

**生活化示例**：手机一键开机——你只按电源键，不必了解 CPU 初始化、内存自检等底层细节。

**Java 示例**：

```java
class CPU    { void start() { System.out.println("CPU 启动"); } }
class Memory { void check() { System.out.println("内存自检"); } }
class Disk   { void read()  { System.out.println("读取系统"); } }

class ComputerFacade {                     // 高层接口:简化子系统调用
    private final CPU cpu = new CPU();
    private final Memory memory = new Memory();
    private final Disk disk = new Disk();

    void powerOn() {                       // 一键调用一组子系统
        cpu.start();
        memory.check();
        disk.read();
    }
}
```

#### 6. 享元模式（Flyweight）

**定义**：运用共享技术有效地支持大量细粒度的对象。

**关键词**：`共享技术`、`大量细粒度对象`、`减少重复创建`、`内部状态共享/外部状态传入`

**典型场景**：Integer.valueOf(-128~127) 缓存、字符串常量池、围棋棋子、数据库连接池

**生活化示例**：共享单车——大家共用同一批车而不是每人买一辆，扫码信息（外部状态）区分谁在骑哪辆。

**Java 示例**：

```java
class Flyweight {                          // 可共享的细粒度对象
    private final String intrinsicState;   // 内部状态(可共享)
    Flyweight(String s) { this.intrinsicState = s; }
    void operation(String extrinsic) {     // 外部状态由客户传入
        System.out.println(intrinsicState + " 被 " + extrinsic + " 使用");
    }
}

class FlyweightFactory {                   // 享元工厂:缓存池
    private final Map<String, Flyweight> pool = new HashMap<>();
    Flyweight get(String key) {
        return pool.computeIfAbsent(key, Flyweight::new);   // 有则复用
    }
}
```

#### 7. 代理模式（Proxy）

**定义**：为其他对象提供一种代理，以控制对这个对象的访问。

**关键词**：`提供代理`、`控制对这个对象的访问`、`真实对象前加一道关卡`

**典型场景**：Spring AOP 动态代理（JDK/CGLIB）、RPC 远程代理、图片懒加载（虚拟代理）、权限校验（保护代理）

**生活化示例**：明星的经纪人——想找明星演出必须先过经纪人这一关，由他控制见不见、何时见。

**Java 示例**：

```java
interface Subject { void request(); }

class RealSubject implements Subject {     // 真实主题
    public void request() { System.out.println("真实业务处理"); }
}

class Proxy implements Subject {           // 代理:控制对真实对象的访问
    private final RealSubject real = new RealSubject();

    public void request() {
        checkAuth();                       // 访问前置控制
        real.request();                    // 委托给真实对象
    }
    private void checkAuth() { System.out.println("权限校验"); }
}
```

### 三、 行为型模式（11种）

**关注"对象之间怎样相互协作、分配职责"，让算法和职责的分配更清晰。**

#### 1. 责任链模式（Chain of Responsibility）

**定义**：使多个对象都有机会处理请求，从而避免请求的发送者和接收者之间的耦合关系。将这些对象连成一条链，并沿着这条链传递请求，直到有一个对象处理它为止。

**关键词**：`多个对象有机会处理请求`、`沿链传递请求`、`直到有一个对象处理它为止`、`避免发送者与接收者耦合`

**典型场景**：Servlet Filter 过滤器链、拦截器链、OA 审批流程、异常处理机制

**生活化示例**：报销审批——小组长签不了转经理、经理签不了转总监，逐级传递直到有人批准。

**Java 示例**：

```java
abstract class Handler {
    protected Handler next;                // 下一个处理者
    Handler linkTo(Handler next) { this.next = next; return next; }
    abstract void handle(int days);
}

class Manager extends Handler {
    void handle(int days) {
        if (days <= 3) System.out.println("经理批准");
        else if (next != null) next.handle(days);   // 沿链传递
    }
}

class Director extends Handler {
    void handle(int days) {
        if (days <= 7) System.out.println("总监批准");
        else if (next != null) next.handle(days);
    }
}
```

#### 2. 命令模式（Command）

**定义**：将一个请求封装为一个对象，从而使你可用不同的请求对客户进行参数化，对请求排队或记录请求日志，以及支持可撤销的操作。

**关键词**：`请求封装为对象`、`请求排队/记录日志`、`支持可撤销(Undo)`、`发出者与执行者解耦`

**典型场景**：线程池提交 Runnable/Callable、GUI 按钮、数据库事务回滚、宏命令、Ctrl+Z 撤销

**生活化示例**：餐厅点菜——顾客把要求写在订单上，服务员把订单递给厨房；顾客不用认识厨师，订单还可撤销重做。

**Java 示例**：

```java
interface Command {                        // 请求 => 对象
    void execute();
    void undo();
}

class Light {
    void on()  { System.out.println("灯亮"); }
    void off() { System.out.println("灯灭"); }
}

class LightOnCommand implements Command {
    private final Light light;
    LightOnCommand(Light light) { this.light = light; }
    public void execute() { light.on(); }
    public void undo()    { light.off(); }         // 支持撤销
}

class Invoker {                            // 调用者(如遥控器/线程池)
    void submit(Command cmd) { cmd.execute(); }    // 还可实现排队/记日志
}
```

#### 3. 解释器模式（Interpreter）

**定义**：给定一个语言，定义它的文法的一种表示，并定义一个解释器，这个解释器使用该表示来解释语言中的句子。

**关键词**：`给定一个语言`、`文法的表示`、`解释器解释句子`、`表达式求值`

**典型场景**：正则表达式引擎、SQL 解析、SpEL/EL 表达式求值、编译器语法树

**生活化示例**：翻译官按固定的语法规则把外语句子逐词解析后翻译成中文。

**Java 示例**：

```java
interface Expression { int interpret(); }

class NumberExp implements Expression {    // 终结符表达式
    private final int value;
    NumberExp(int v) { this.value = v; }
    public int interpret() { return value; }
}

class AddExp implements Expression {       // 非终结符表达式(一条文法规则)
    private final Expression left, right;
    AddExp(Expression l, Expression r) { left = l; right = r; }
    public int interpret() { return left.interpret() + right.interpret(); }
}

// 使用:new AddExp(new NumberExp(1), new NumberExp(2)).interpret(); // 结果 3
```

#### 4. 迭代器模式（Iterator）

**定义**：提供一种方法顺序访问一个聚合对象中的各个元素，而又不暴露该对象的内部表示。

**关键词**：`顺序访问聚合对象的各个元素`、`不暴露内部表示`、`hasNext()/next()`

**典型场景**：Java 的 Iterator/ListIterator、for-each 循环底层实现、集合框架统一遍历

**生活化示例**：图书管理员从书架上一本本往外递书，你只需说"下一本"，不必知道书架如何摆放。

**Java 示例**：

```java
interface MyIterator<T> {
    boolean hasNext();
    T next();
}

class Bookshelf {
    private final String[] books = {"Java", "Python", "Go"};

    MyIterator<String> iterator() {
        return new MyIterator<>() {        // 隐藏数组这一内部表示
            private int index = 0;
            public boolean hasNext() { return index < books.length; }
            public String next()     { return books[index++]; }   // 顺序访问
        };
    }
}
```

#### 5. 中介者模式（Mediator）

**定义**：用一个中介对象来封装一系列的对象交互。中介者使各对象不需要显式地相互引用，从而使其耦合松散，而且可以独立地改变它们之间的交互。

**关键词**：`封装一系列对象交互`、`不需要显式相互引用`、`耦合松散`、`网状交互变星状`

**典型场景**：MVC 中的 Controller、聊天室服务器、机场塔台调度、房屋中介

**生活化示例**：机场塔台——所有飞机只和塔台通信，飞机之间不需要互相协调航线。

**Java 示例**：

```java
interface Mediator { void relay(User from, String msg); }

class User {
    private final String name;
    private final Mediator mediator;       // 只认识中介者,不认识其他用户
    User(String name, Mediator m) { this.name = name; this.mediator = m; }
    void send(String msg)      { mediator.relay(this, msg); }
    void receive(String msg)   { System.out.println(name + " 收到: " + msg); }
    String getName()           { return name; }
}

class ChatRoom implements Mediator {       // 封装所有对象间的交互
    private final List<User> users = new ArrayList<>();
    void join(User u) { users.add(u); }
    public void relay(User from, String msg) {
        for (User u : users)
            if (u != from) u.receive(from.getName() + ": " + msg);
    }
}
```

#### 6. 备忘录模式（Memento）

**定义**：在不破坏封装性的前提下，捕获一个对象的内部状态，并在该对象之外保存这个状态。这样以后就可将该对象恢复到原先保存的状态。

**关键词**：`不破坏封装性`、`捕获内部状态并在对象之外保存`、`恢复到原先保存的状态`

**典型场景**：游戏存档、编辑器 Ctrl+Z、数据库事务回滚、浏览器后退

**生活化示例**：打 Boss 前先存档——打输了读档回到存档那一刻的状态重新来过。

**Java 示例**：

```java
class Memento {                            // 备忘录:存放状态快照
    private final String state;
    Memento(String state) { this.state = state; }
    String getState() { return state; }
}

class Originator {                         // 原发器
    private String state;
    void setState(String s)  { state = s; }
    Memento save()           { return new Memento(state); }      // 捕获状态
    void restore(Memento m)  { state = m.getState(); }           // 恢复状态
}

class Caretaker {                          // 管理者:只负责保存,不查看内容
    private Memento memento;
    void store(Memento m)    { memento = m; }
    Memento retrieve()       { return memento; }
}
```

#### 7. 观察者模式（Observer）

**定义**：定义了一种一对多的依赖关系，让多个观察者对象同时监听某一个主题对象。当这个主题对象的状态发生变化时，会通知所有观察者对象，使它们能够自动更新自己。

**关键词**：`一对多的依赖关系`、`状态发生变化时通知所有观察者`、`自动更新`、`发布-订阅`

**典型场景**：微信公众号推送、GUI 事件监听（Listener）、消息队列发布订阅、Spring 事件机制

**生活化示例**：关注公众号——号主一发文章（主题变化），所有粉丝（观察者）自动收到推送。

**Java 示例**：

```java
interface Observer {
    void update(String msg);
}

class Fan implements Observer {            // 观察者
    private final String name;
    Fan(String name) { this.name = name; }
    public void update(String msg) { System.out.println(name + " 收到推送: " + msg); }
}

class OfficialAccount {                    // 主题(被观察者):一对多
    private final List<Observer> observers = new ArrayList<>();
    void follow(Observer o) { observers.add(o); }
    void publish(String msg) {
        for (Observer o : observers) o.update(msg);   // 变化 => 通知所有观察者
    }
}
```

#### 8. 状态模式（State）

**定义**：允许一个对象在其内部状态改变时改变它的行为，对象看起来似乎修改了它的类。

**关键词**：`内部状态改变时改变它的行为`、`看起来似乎修改了它的类`、`状态驱动行为`、`替代大量 if-else`

**典型场景**：订单状态流转（待付款/已发货/已完成）、电梯运行状态、线程状态机、游戏角色状态

**生活化示例**：红绿灯——灯色（状态）一切换，行人车辆的通行行为随之改变。

**Java 示例**：

```java
interface OrderState {
    void pay(Order ctx);
    void ship(Order ctx);
}

class Order {                              // 环境类:持有当前状态
    OrderState state = new UnpaidState();
    void setState(OrderState s) { state = s; }    // 状态改变 => 行为改变
}

class UnpaidState implements OrderState {
    public void pay(Order ctx)  { ctx.setState(new ShippedPaidState()); }  // 切换状态
    public void ship(Order ctx) { System.out.println("未付款不能发货"); }
}

class ShippedPaidState implements OrderState {
    public void pay(Order ctx)  { System.out.println("已付款,请勿重复支付"); }
    public void ship(Order ctx) { System.out.println("已发货"); }
}
```

#### 9. 策略模式（Strategy）

**定义**：定义一系列的算法，把它们一个个封装起来，并且使它们可以相互替换。本模式使得算法可独立于使用它的客户而变化。

**关键词**：`一系列算法`、`一个个封装起来`、`可以相互替换`、`算法独立于使用它的客户而变化`

**典型场景**：Comparator 排序策略、支付方式选择（微信/支付宝/银联）、促销折扣算法、导航路线规划

**生活化示例**：回家选交通工具——地铁、打车、骑车是三种"策略"，按天气和钱包随时替换，目的地不变。

**Java 示例**：

```java
interface PaymentStrategy {                // 算法族
    void pay(double amount);
}

class WechatPay implements PaymentStrategy {
    public void pay(double amount) { System.out.println("微信支付 " + amount); }
}
class AliPay implements PaymentStrategy {
    public void pay(double amount) { System.out.println("支付宝支付 " + amount); }
}

class Checkout {                           // 环境:算法之间可以相互替换
    private PaymentStrategy strategy;
    void setStrategy(PaymentStrategy s) { strategy = s; }
    void checkout(double amount)         { strategy.pay(amount); }
}
```

#### 10. 模板方法模式（Template Method）

**定义**：定义一个操作中的算法的骨架，而将一些步骤延迟到子类中。模板方法使得子类可以不改变一个算法的结构即可重定义该算法的某些特定步骤。

**关键词**：`算法的骨架`、`步骤延迟到子类中`、`重定义该算法的某些特定步骤`、`父类定流程子类填内容`

**典型场景**：JdbcTemplate、HttpServlet 的 service/doGet/doPost 分发、JUnit 测试生命周期、钩子方法

**生活化示例**：泡茶流程固定（烧水→放料→冲泡→倒入杯中），放什么料（茶叶还是咖啡粉）由子类说了算。

**Java 示例**：

```java
abstract class Beverage {
    final void make() {                    // 模板方法:固定算法骨架(final 防改流程)
        boilWater();
        brew();                            // 变化步骤 => 延迟到子类
        pourInCup();
    }
    private void boilWater()  { System.out.println("烧开水"); }
    private void pourInCup()  { System.out.println("倒入杯中"); }
    abstract void brew();                  // 子类重定义特定步骤
}

class Tea extends Beverage {
    void brew() { System.out.println("浸泡茶叶"); }
}
class Coffee extends Beverage {
    void brew() { System.out.println("冲泡咖啡粉"); }
}
```

#### 11. 访问者模式（Visitor）

**定义**：表示一个作用于某对象结构中的各元素的操作。它使你可以在不改变各元素的类的前提下，定义作用于这些元素的新操作。

**关键词**：`作用于某对象结构中的各元素的操作`、`不改变各元素的类的前提下定义新操作`、`双分派`、`数据与操作分离`

**典型场景**：编译器 AST 遍历（语义分析/代码生成）、报表统计、XML 文档解析

**生活化示例**：单位团检——同一批人（对象结构）遇到不同科室医生（访问者）做完全不同的检查；新增检查项目也不用改动受检者本人。

**Java 示例**：

```java
interface Visitor {
    void visit(FileEl f);
    void visit(Folder f);
}

interface Element {                        // 双分派入口
    void accept(Visitor v);
}

class FileEl implements Element {
    final String name;
    FileEl(String n) { name = n; }
    public void accept(Visitor v) { v.visit(this); }   // 反向回调访问者
}

class Folder implements Element {
    final String name;
    Folder(String n) { name = n; }
    public void accept(Visitor v) { v.visit(this); }
}

class SizeVisitor implements Visitor {     // 新增操作无需修改任何元素类
    public void visit(FileEl f)  { System.out.println("统计文件大小: " + f.name); }
    public void visit(Folder f)  { System.out.println("进入文件夹: " + f.name); }
}
```
