## 数据流图

> 数据流图（Data Flow Diagram，DFD）是结构化分析（Structured Analysis，SA）方法中描述系统"数据流向"的建模工具，是软考软件设计师下午案例分析题的必考内容。

### 结构化分析方法

结构化开发方法分为：结构化分析（SA）、结构化设计（SD）、结构化程序设计（SP）。

- 结构化分析（SA）的核心思想：自顶向下、逐层分解
- 结构化分析的输出：数据流图（DFD）+ 数据字典（DD）+ 加工说明（判定表/判定树/结构化语言）
- 面向数据流的建模方法，围绕**数据**而非功能建模

### 数据流图的基本元素

数据流图由 4 种基本元素构成：

| 元素 | 图形符号 | 说明 |
| ---- | ---- | ---- |
| 外部实体（External Entity） | 矩形 | 指系统之外的人、组织或系统，是数据的**源点**或**终点** |
| 加工/处理（Process） | 圆角矩形或圆圈 | 对数据流进行变换的处理过程，必须有**输入**和**输出** |
| 数据流（Data Flow） | 带箭头的直线 | 数据的流动方向，由箭头表示流向，线上标注数据名 |
| 数据存储（Data Store） | 开口矩形（双杠） | 数据的静态存储，即数据文件或数据库 |

要点：

- 数据流是**有方向**的，箭头指向表示数据流动的方向
- 每条数据流都必须有**名称**（数据的名字）
- 数据流只能从加工流向加工、从加工流向存储/实体、从实体/存储流向加工，**数据流不能在实体之间直接流动**，也不允许在存储之间直接流动
- 一个加工可以有多个输入/输出数据流

### 数据流图的层次结构

采用**自顶向下、逐层分解**的方法，数据流图分为：

| 层次 | 名称 | 内容 |
| ---- | ---- | ---- |
| 顶层图 | 顶层数据流图 / 上下文图 | 只有一个加工，代表整个系统，描述系统与外部实体的数据交互 |
| 0 层图 | 0 层数据流图 | 将顶层图中的加工分解为若干个子加工，描述系统的**主要功能** |
| 1 层图 | 1 层数据流图 | 对 0 层图中的加工进一步分解，依此类推 |

- 顶层图只有一个加工，该加工代表整个系统
- 0 层图是最重要的一张图，它刻画了系统的主要功能模块
- 分解的层次、加工的粒度由系统的复杂程度决定

### 数据流图的平衡规则（重点）

#### 父图与子图的平衡

> 子图的输入/输出数据流应与父图对应加工的输入/输出数据流**完全一致**，即数据流的个数和方向必须相同（可合并为组合数据流）。

- 即：在父图中某加工有 N 条输入、M 条输出，则其子图也必须对应有 N 条输入、M 条输出
- 输入/输出数据流可以分别合并为一条（多条流合并成一条组合流），但合并前的分解必须可还原

#### 加工的输入与输出平衡（守恒）

> 一个加工必须有输入也必须有输出，且输入数据流与输出数据流的内容应守恒。

- **只有输入没有输出的加工是黑洞**：错误
- **只有输出没有输入的加工是奇迹/白洞**：错误
- 一个加工的输出不能凭空产生，必须有对应的输入数据流来支撑

### 数据字典（Data Dictionary，DD）

数据字典是数据流图中所有元素的定义集合，是数据流图的重要补充。

- 定义对象：数据流、数据存储、数据项（数据元素）、加工、外部实体
- 作用：对数据流图中的各元素给出精确定义，是系统分析与设计的依据

数据字典的常用符号：

| 符号 | 含义 |
| ---- | ---- |
| = | 表示"定义为" |
| + | 表示"与"（和、连接） |
| \| 或 [] | 表示"或"（选择其一） |
| {} | 表示"重复"（0 次或多次） |
| () 或 n..m | 表示"可选"（0 次或 1 次；n..m 表示重复 n 到 m 次） |

数据字典的定义实例：

- 学生成绩单 = 学号 + 姓名 + {课程 + 成绩}
- 考试科目 = (语文 | 数学 | 外语)

### 加工逻辑的描述

加工逻辑（加工说明）用于描述加工"做什么"，常用三种工具：

| 工具 | 特点 | 适用场景 |
| ---- | ---- | ---- |
| 结构化语言 | 介于自然语言与程序设计语言之间，只使用顺序、选择（IF-THEN-ELSE/ELSEIF-ENDIF）、循环（WHILE-DO-ENDDO、REPEAT-UNTIL）三种结构 | 描述逻辑顺序清晰的加工 |
| 判定表 | 以表格形式描述多个条件及其组合下的处理动作 | 条件多、组合多且动作多的加工 |
| 判定树 | 以树形结构描述决策逻辑 | 条件不多但层次清晰的加工 |

判定表构成：条件桩、动作桩、条件项、动作项（规则数 = 各条件取值个数之积）

### 绘制数据流图的步骤

1. 确定系统的**外部实体**（从问题描述中找出人、机构、系统）
2. 确定系统的**输入/输出数据流**（画出顶层图）
3. 将系统分解为若干加工，画出 0 层图
4. 确定数据流（在加工之间、加工与存储/实体之间标出）
5. 确定数据存储
6. 对加工逐层细化，画出子图
7. 检查并完善（平衡检查、守恒检查）

识别数据流的关键：数据流是"数据在流动"，数据存储是"数据的静止状态"，**判断是否含加工（处理）**可区分数据流与数据存储——若数据需要经过处理变换则存在加工。

### 数据流图的常见错误

- 数据流图不满足**父图子图平衡**（子图漏画输入/输出数据流）
- 加工只有输入没有输出（黑洞）或只有输出没有输入（奇迹）
- 数据流在**实体与实体之间**直接流动
- 数据流在**存储与存储之间**直接流动
- 数据流命名缺失或重复
- 一个加工没有输入或没有输出

### 考试答题技巧（下午题）

下午案例分析题常考题型：

1. 补充实体：根据题干描述，找出系统外部的人、组织、系统
2. 补充数据存储：找出需要持久化保存的数据（文件/数据库），常与数据流对应
3. 补充数据流：根据数据流平衡规则、加工的输入输出关系判断
4. 说明数据流图的作用、加工逻辑描述工具的选择等

答题要点：

- 外部实体名称来自题干中的**人员/角色、机构、其它系统**
- 数据存储名称通常是题干中反复出现的**名词性数据**（如订单、学生、成绩）
- 检查平衡：0 层图的数据流应与顶层图一致；子图应与父图对应加工一致
- 数据流箭头方向：加工产生数据 -> 流向存储或实体；外部数据 -> 流入加工
- 注意一个实体可以有多个输入/输出数据流

### 数据流图（DFD）与业务流程图的区分

| 对比项 | 数据流图（DFD） | 业务流程图（TFD） |
| ---- | ---- | ---- |
| 关注点 | 数据的流动与处理 | 业务的处理流程与顺序 |
| 元素 | 数据流、加工、存储、外部实体 | 处理、活动、判定、文档 |
| 强调 | 数据变换、数据存储 | 时间顺序、业务逻辑 |

### 数据流图与系统流程图的关系

- 数据流图描述系统的**逻辑模型**（做什么），不考虑物理实现
- 系统流程图描述系统的**物理模型**（怎么做），考虑具体的设备、程序和文件
- 软件设计中由数据流图（逻辑模型）映射为结构图/模块结构图（物理模型）
